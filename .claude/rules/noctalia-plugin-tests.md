# Plugin tests (`noctalia-plugin/tests/`)

`unittest`, temp XDG dirs, Lua mock `harness.lua`; never real config or a live shell. Add cases for changed behavior and check they can fail. One file: `python tools/check.py test_panel`; all: `check.py plugin host` (shared UI affects the app). Workflow: `add-test`.

| File | Covers |
| --- | --- |

`harness.lua`, the Noctalia API mock: JSON codec, lexical `require` with private module globals, `H.start(name, app)`, `H.env` for `getenv`, `H.settings` (dotted path) for `getSetting`, helper replies per command in `replies` (`return false, text, code` fails with that code); `runAsync` refuses a 9th unanswered command (held calls + live polls), like Noctalia; a new API the UI uses goes here and into `python/umbriel_settings/host/api.py`. `H.clock` is what `noctalia.nowMs()` returns (advance it to spend a time budget); `H.slide(node, value)` drags a slider (change, then release); like Noctalia, `panel.render` calls the previous slider's `onChange` when a render changes its `value`; `H.drag(sourceKey, zoneKey)` drops a drag source on a zone (checks `accepts`, and fails for a zone inside a drag source without `hitSlop`, which Noctalia never hits); `wait-live` calls are held until `H.liveChange(event|nil)` answers them (`H.liveWaits`); `H.hold(cmd)`/`H.release(cmd[, stop])` hold any command (follow-up calls stay held); `H.clipboard` = the last `copyToClipboard` {text, mime}; `H.notifications` = `noctalia.notify` bodies; a released held call can be held again, so drain with `H.release(cmd, true)` between flows; `H.screen()` is cut to 600 chars for messages, `H.fullScreen()` for searching; `H.walk(node, visit)`, `H.byKey(key)`, `H.input(pattern)` (input by key pattern), `H.goHome()` (Ctrl+F + empty search). It doesn't prove live rendering or Noctalia's own CPU accounting.
