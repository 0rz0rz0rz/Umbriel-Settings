# Plugin tests (`noctalia-plugin/tests/`)

`unittest`, temp XDG dirs, Lua mock `harness.lua`; never real config or a live shell. Add cases for changed behavior and check they can fail. One file: `python tools/check.py test_panel`; all: `check.py plugin host` (shared UI affects the app). Workflow: `add-test`.

| File | Covers |
| --- | --- |
| `support.py` | `HelperTestCase` (temp root with `data/`, `xdg-config/`, `share/` as XDG dirs; `reply`/`ok`/`fails`/`expect` run the helper), `DesktopTestCase` (one desktop file: `FILE` at `self.path`, its `PART` via `read()`/`save(revision, changes)`, `self.backup`) and `ConfigTestCase` (+ `CONFIG` at `self.config`, `FAKE_UMBRIEL` first on `PATH`; `test_umbriel_settings.py` builds `ConfigHelperTestCase` on it) |
| `test_umbriel_settings.py` | helper commands (meta, read, preview, save, entries, maps, keybinds and locks, backups, config path, title-bar follow per config, malformed requests, `internal` replies, `windows`/`layers`/`focused-window`/`wait-live`/`xkb`/`run-action`, `preview` with `check`, `list-dir` and `pick-file`/`pick-folder` mapping a `chosen` path in `FileBrowserTests`) with the fake `umbriel` (answers `windows`/`layers`/`focused-window`/`keyboard-layouts --json`, `subscribe` (each event's state, then `$SUB_CHANGE`'s change); `msg` appends its argv to `$MSG_LOG`, fails with `$MSG_FAIL`); `RealUmbrielTests` round-trips the stock config through the installed one (skipped without it); `LauncherTests`: the standalone launcher `launch-app` (real-`gio` test skipped without it) |
| `test_user_dirs.py`, `test_default_apps.py` | `desktop`/`desktop-save`/`extension`/`app-command` (timestamped backups, localized app names, `OnlyShowIn`/`NotShowIn`: set `LANG`/`XDG_CURRENT_DESKTOP` in `self.env`) |
| `test_panel.py` | manifest checks; builds fixtures with the real helper, then runs under plain `lua` (skipped without it: report the skip): `panel_test.lua` (plugin layout flows, incl. open-window/layer pickers and their live refresh, Use the focused window, named curve/effect/output choices, action argument picker, Browse… (the panel's file browser, autostart app list), the XKB page, Run now), `state_test.lua` (drafts, discard, undo, redo, reopening mid-request, inputs reused between entries), `app_test.lua` (app layout: sidebar, search, locale, Escape, keybind Record…), `outputs_test.lua` (`arrange`/`displays` geometry, display tiles, drop/undo, default star, names, mode selects, Try), `bar_test.lua`, `budget_test.lua` (every page on a large config plus XKB-sized lists and 300 open windows, and a 2000-entry folder in the file browser, each callback ≤ 25 ms, mock JSON excluded) |

`harness.lua`, the Noctalia API mock: JSON codec, lexical `require` with private module globals, `H.start(name, app)`, `H.env` for `getenv`, `H.settings` (dotted path) for `getSetting`, helper replies per command in `replies`; a new API the UI uses goes here and into `python/umbriel_settings/host/api.py`. `H.clock` is what `noctalia.nowMs()` returns (advance it to spend a time budget); `H.slide(node, value)` drags a slider (change, then release); like Noctalia, `panel.render` calls the previous slider's `onChange` when a render changes its `value`; `H.drag(sourceKey, zoneKey)` drops a drag source on a zone (checks `accepts`, and fails for a zone inside a drag source without `hitSlop`, which Noctalia never hits); `wait-live` calls are held until `H.liveChange(event|nil)` answers them (`H.liveWaits`); `H.hold(cmd)`/`H.release(cmd[, stop])` hold any command (follow-up calls stay held); `H.clipboard` = the last `copyToClipboard` {text, mime}; `H.screen()` is cut to 600 chars for messages, `H.fullScreen()` for searching; `H.walk(node, visit)`, `H.byKey(key)`, `H.input(pattern)` (input by key pattern), `H.goHome()` (Ctrl+F + empty search). It doesn't prove live rendering or Noctalia's own CPU accounting.
